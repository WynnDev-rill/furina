# Furina Identity Core

[Nomi Identity Core](https://nomi.ai/updates/introducing-the-nomi-identity-core-fostering-dynamic-and-authentic-identities/) describes a private and evolving identity that uses interactions and feedback alongside memory. [Nomipedia](https://wiki.nomi.ai/What_Is_The_Identity_Core) distinguishes its autonomous development from user-authored backstory. The vendor's public material describes behavior and leaves database structure, models, and promotion thresholds undocumented. [Kindroid](https://kindroid.ai/v2/docs/memory/) provides bounded learned context and stable reference memories, while [Character.AI](https://support.character.ai/hc/en-us/articles/52739596326811-Lorebooks) retrieves world information on demand.

Furina keeps a fixed character anchor, user's persona guidance, retrieved facts and episodes, and a small evolving identity. The same identity is used in conversations and proactive greetings, with emotion inferred from the current interaction. A small model reviews at most once per six distinct turns and 30 minutes. It may propose preferences, stances, relationship patterns, or shared rituals. A proposal requires an exact supporting excerpt from the review turn. A second review must corroborate the same key in a different thread or after a day. A grounded explicit reversal can remove it. Candidate and accepted entries are capped at eight each. Only accepted entries enter the reply prompt. Exact excerpts are used for validation and discarded.

The private table uses RLS, server-only access and optimistic revision checks. Authenticated sessions use their verified Supabase ID. Guest continuity uses the existing private browser UUID, and survives reopening on that browser. Guest evolution is scoped separately from signed-in evolution. Identity remains private, while Character & Appearance provides pause and reset. Reset clears learned identity and pending evidence. Clearing all memories also resets learned identity. The migration preserves existing memories, and the application stops generating or retrieving legacy self-notes for replies and stops folding them into new automatic summaries.

Run `node --test tests/identity-core.test.mjs`, `bunx tsc --noEmit`, and `bun run build`. Apply the migration before publishing the web build. Verify the control in a guest browser, an independent browser identity, and an authenticated test account where available. Model judgment is probabilistic, and selective reviews can miss changes occurring between reviews. Candidate corroboration and fixed constraints reduce drift without evaluating model outputs as ground truth.
